There are two bugs in the topic filtering system. Fix both surgically — do not refactor or restructure anything else.

==============================================================
BUG 1 — Wrong articles show when multiple topics are selected
==============================================================

FILE: storage.ts (lines 20–35)

ROOT CAUSE:
When "Trending" is included alongside other topics (e.g. ["Trending", "Tech"]),
the current code detects "Trending" and skips topic filtering entirely.
This means Tech, Science, etc. are silently ignored.

CURRENT BROKEN LOGIC (approximately):
  if (topics.includes("Trending")) {
    // skip WHERE topic clause → returns ALL topics for region
  } else if (topics.length === 1) {
    WHERE topic = $1
  } else {
    WHERE topic IN (...)
  }

FIX:
Split "Trending" and real topic filters into two separate concerns:

  const hasTrending = topics.includes("Trending");
  const realTopics = topics.filter(t => t !== "Trending");

  // Build the topic WHERE clause only from realTopics
  if (realTopics.length === 1) {
    query += ` AND topic = $${paramIndex}`;
    params.push(realTopics[0]);
    paramIndex++;
  } else if (realTopics.length > 1) {
    const placeholders = realTopics.map((_, i) => `$${paramIndex + i}`).join(", ");
    query += ` AND topic IN (${placeholders})`;
    params.push(...realTopics);
    paramIndex += realTopics.length;
  }
  // hasTrending only controls ORDER BY, not WHERE — see Bug 2 fix below

==============================================================
BUG 2 — "Trending" does not actually sort by trending/recency
==============================================================

FILE: storage.ts (same function)

ROOT CAUSE:
"Trending" currently bypasses the topic WHERE clause but does NOT apply
any special sort order. The result is just the default query order,
which means all articles for the region appear, unsorted by popularity
or recency — so it feels like the filter did nothing.

FIX:
Make "Trending" control ORDER BY, not WHERE:

  // After building the WHERE clause (from Bug 1 fix above):
  if (hasTrending) {
    // Sort by most recent first — use publishedAt descending
    // If you have an "importance" or "views" column, sort by that too
    query += ` ORDER BY published_at DESC`;
  } else {
    query += ` ORDER BY published_at DESC`; // default — keep consistent
  }

  // In future: if a "score" or "views" column exists, Trending can use:
  // ORDER BY score DESC, published_at DESC

==============================================================
BUG 4 — Topics filter resets when switching regions
==============================================================

FILE: Home.tsx

ROOT CAUSE:
If region change triggers a re-render or re-mount that re-reads
localStorage without preserving the current in-memory topics state,
the topics reset to the default.

FIX:
When region changes, update ONLY the region key in the filters state,
not the entire filters object:

  // WRONG — this resets topics:
  setFilters({ region: newRegion, topics: defaultTopics });

  // CORRECT — preserve existing topics:
  setFilters(prev => ({ ...prev, region: newRegion }));

Also ensure the region selector's onChange handler uses the functional
updater form above, not a full object replacement.
